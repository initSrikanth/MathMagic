# Recover Codex work from GitHub

Conversation history is not a checkpoint. Start with the repository and the existing PR; preserve all local user changes and approved media.

1. Fetch the PR metadata, body, issue/review comments, review threads, commits, base/head refs and exact head SHA. For PR59: `gh pr view 59 --repo initSrikanth/MathMagic --json number,state,headRefName,headRefOid,baseRefName,baseRefOid,commits,statusCheckRollup,body,url`. Never infer completion from an earlier conversational summary.
2. Inspect `git status`, remote URL and existing work before fetching/checking out the head. Fetch explicit refspecs, because this environment can track only main by default: `git fetch origin feature/measurement-production-pilot:refs/remotes/origin/feature/measurement-production-pilot`. Use the existing branch or an isolated checkout; do not reset, force-push or overwrite uncommitted work.
3. Read `AGENTS.md`, applicable topic/video rules, `tools/production/README.md` and `docs/pr59-recovery-checkpoint.md` from that head. Follow their authority and holds. A green workflow is not a release approval.
4. Query workflow runs for the **current head**, including attempts and actual job conclusions: `gh run list --repo initSrikanth/MathMagic --commit HEAD_SHA`. Record the PR merge-test SHA separately from the source head; Actions may test `refs/pull/59/merge`. Fetch actual readiness logs/report, source/student-flow/live receipts and browser diagnostics from the matching run. Do not mix receipts from different runs or source commits.
5. Download the named artifacts while retained: `gh run download RUN_ID --repo initSrikanth/MathMagic --dir /tmp/pr59-recovered`. Preserve artifact IDs, digests and expiry. If a runner network cannot access an artifact redirect, use the connected GitHub artifact/log tools; readiness job logs contain the rendered report. Missing/expired downloads are not PASS. A report recovered from logs is historical evidence, not a complete local checkpoint cache.
6. Compare profile/rule/input/runtime/log hashes before reuse. `python tools/production/pilot.py run --resume --stages ...` only reuses intact, compatible **local** checkpoints. Restored historical GitHub receipts retain their run/source context; CI deliberately runs fresh at a new head and rejects stale, dirty or wrong-run evidence. Do not edit receipts to make them current. Reuse unchanged approved media and its checksum-bound canonical evidence; do not regenerate it or repeat paid calls.
7. Resume only unfinished or invalidated stages. For a transient CI failure, inspect the actual log and use **Re-run failed jobs**, preserving successful job artifacts. Changed source needs relevant fresh tests and final-head required CI. Auth-isolated browser tests, emulator rules and Linux WebKit never become live Firebase or physical Safari evidence.
8. Save source, scripts, alignment, asset hashes, failures, pending flags and next actions in a commit on the same PR branch. Update this checkpoint and the PR body with exact SHAs, run links, PASS/FAIL/UNVERIFIED distinctions, credit usage and release blockers. Never persist credentials, signed URLs or fabricated human attestations.
9. Before ending a session, confirm the remote branch SHA, checks and readiness state from GitHub. Keep blocked work unmerged and unpublished. A later session repeats these read-only checks, then continues from the durable checkpoint.

For this environment, connector GitHub reads are available when local `gh`/Git cannot reach the inherited proxy. Ordinary sandbox networking may be unavailable; use the approved execution permission mechanism for the same scoped command. An explicit network-policy denial requires the environment configuration flow; do not bypass it or disable TLS verification.

Permanent committed evidence must summarise essential outcomes because Actions artifacts expire. Artifacts supplement the checkpoint with detailed logs; the checkpoint must name unfinished actions honestly so their expiry does not trigger repeat generation.
