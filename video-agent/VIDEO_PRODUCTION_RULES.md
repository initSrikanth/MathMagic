# MathMagic video production rules

1. Mathematics is the main subject; position the approved teacher full-body on the left with no unnecessary enclosing frame.
2. Reuse approved presenter footage and voice. Never spend HeyGen credits to regenerate existing footage.
3. Generate mathematics with Python/SVG/FFmpeg, not HeyGen.
4. Change board content whenever the teaching point changes; a single equation must never remain on screen for an entire explanation.
5. Review narration and map visuals to spoken concepts before rendering; check transitions at multiple timestamps.
6. Validate every fraction, equality, inequality, bar model, and number-line placement.
7. Compare fractions using the same-size whole; maintain legible horizontal fraction bars.
8. Preserve the presenter's full height, shoes, clothing, voice, and natural movement. Do not add a frame around the presenter.
9. Begin directly with the topic; do not add "Welcome to MathMagic" or similar unnecessary introductions.
10. For future HeyGen footage request slightly more natural facial expression and subtle body and hand movements, without obscuring mathematics.
11. Export browser-compatible H.264/yuv420p video and AAC audio in MP4.
12. Check scene changes, complete audio, cropping, resolution, and mobile playback.
13. Keep the previous video available until the replacement has been rendered and tested.
14. Publish the video file to GitHub before claiming the webpage is updated; verify that the HTML video source resolves.
15. Do not change authentication, student progress, or unrelated lessons.
16. Verify the live deployed video, not just a successful code commit.
17. Preserve originals and source scripts so edits can be repeated without paid generation.
18. Report the commit SHA, live video URL, and any remaining failed checks accurately.

## Workflow
Analyse -> storyboard -> create changing visuals -> synchronise -> composite -> validate -> publish -> live playback verification.
